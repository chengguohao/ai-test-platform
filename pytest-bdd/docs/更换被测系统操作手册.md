# 更换被测系统操作手册

> 目标：把本框架（pytest-bdd）从**强绑定 SmartAdmin** 迁移到新被测系统（下文代称 `{SYS}`），
> 最小改动、逐步验证、不污染现有 SmartAdmin 用例。
>
> 适用读者：测试工程师 / AI 协作开发者。前置阅读：[docs/框架执行流程说明.md](框架执行流程说明.md)。

---

## 0. 先看清绑定面：框架里只有 3 处是真绑定

阅读结论（来自代码现状）：

| 模块 | 与 SmartAdmin 的关系 | 换系统时 |
|---|---|---|
| `support/api_case.py` | 通用 DSL，含 SmartAdmin 信封扩展（`biz_ok`/`biz_fail`/`biz_auto`） | 「半通用」：信封字段名可能需调整，或用 `biz_auto=False` 规避 |
| `support/clients/api_client.py` | 通用 HTTP 客户端 + SmartAdmin 信封解析 / token 注入 / 重登钩子 | 「半通用」：token 注入方式、信封解析字段可能要改 |
| `support/fixtures/context.py` | 完全通用（占位符串联） | **不用动** |
| `support/fixtures/smartadmin.py` | **整文件 SmartAdmin 专属**：SM4 登录、验证码、错误码探测（写死 `/oa/enterprise/*`）、角色池、清理注册 | **必须整文件替换为 `{SYS}` adapter** |
| 根 `tests/conftest.py` | 全局日志钩子，硬 `import SA_ROLE_CLIENTS` | 改 import 目标 adapter（或改注册式） |
| `tests/api/smartadmin/`、`tests/acceptance/smartadmin/` | 用例层，全部依赖 `sa_*` fixture 与 `smartadmin` marker | 按新系统目录重建 |
| `tools/openapi_gen.py` | 对接 SmartAdmin `/v3/api-docs` | 换目标系统 OpenAPI 地址 |

**结论：换系统 = 换 adapter（smartadmin.py）+ 换目录 conftest + 改 3 处半通用点，DSL/日志/报告引擎不需要动。**

## 1. 决策先行：回答 2 个问题（决定改动量）

### Q1：目标系统的鉴权形态？（决定登录 adapter 写多少）

| 形态 | 典型场景 | 登录 adapter 工作量 |
|---|---|---|
| A. 匿名直连 | 内网测试环境、不做鉴权 | 最小（跳过登录即可） |
| B. 固定 token | Header 里写死鉴权串 / 单账号会话 | 小（读配置注入 Header） |
| C. 登录接口 + token | 账号密码登录，返回 token 放 Header 或 Cookie | 中（写一个 `{sys}_login`） |
| D. OAuth2 / JWT 刷新 | 复杂授权 + token 过期刷新 | 大（借用 `set_relogin_hook` 机制） |

### Q2：目标系统的响应信封？（决定信封守卫怎么设）

| 形态 | 示例 | 信封守卫处理 |
|---|---|---|
| A. `{ok, code, msg, data}`（SmartAdmin 风格） | `{"ok":true,"code":0,"msg":"操作成功"}` | 直接复用，只换登录 |
| B. `{code, msg, data}`（成功码约定） | `{"code":0,"msg":"ok"}` / `code!=0` 即失败 | 把 `biz_ok/biz_fail` 的 `/ok` 断言去掉，保留 `/code` |
| C. 纯 HTTP 语义（RESTful） | 2xx=成功、4xx/5xx=失败 | 每条用例 `biz_auto=False`，断言状态码/响应体字段 |
| D. 混合 | 业务模块各自为政 | 按接口模块区分（正例靠守卫、异常显式断言） |

> **建议先做「最小接入」（第 2 章）摸清 Q1/Q2，再决定「完整接入」（第 3 章）改多少。**

## 2. 最小接入：10 分钟先跑通（不改任何旧文件）

目标：验证「新系统接口 + 本框架 DSL」能通，建立信心。全程只新增文件。

### 2.1 新建配置 `.env.{SYS}`

```ini
# ===== {SYS} 被测系统环境变量 =====
{SYS}_BASE_URL=http://127.0.0.1:8080
# 表单A/B用：登录用户名 / 密码（或固定 token）
{SYS}_LOGIN_NAME=admin
{SYS}_PASSWORD=
{SYS}_TOKEN=
```

> 注意：`.env` 里的 `SA_*` 保持原样（不影响），新系统用独立变量名。

### 2.2 写最简 adapter `support/fixtures/{sys}.py`

复制 `support/fixtures/smartadmin.py` 后删减，先只保留一块——**登录会话**：

```python
"""{SYS} 最小 adapter：先只做登录/会话，业务码探测与清理稍后补。"""
from __future__ import annotations

import os
import pytest
from support.clients.api_client import ApiClient

def {sys}_login(client: ApiClient, login_name: str | None = None,
                password: str | None = None) -> None:
    """按 {SYS} 鉴权协议登录，成功后 token 写入 client.token。"""
    base = client.base_url.rstrip("/")
    # 形态C（登录型）示例：POST /login -> {"token": "..."}
    # 形态A/B 可直接 return（见 2.4 的 token 注入兜底）
    raise NotImplementedError("按目标系统鉴权协议实现，见第 3.2 节三种形态模板")

def make_{sys}_fixture_functions():
    def {sys}_base_url() -> str:
        return os.getenv("{SYS}_BASE_URL", "http://127.0.0.1:8080").rstrip("/")

    def {sys}_api_client(base_url):
        client = ApiClient(base_url)
        # 形态B：固定 token 直接注入，无需登录
        token = os.getenv("{SYS}_TOKEN", "").strip()
        if token:
            client.token = token
        yield client
        client.close()

    return ({sys}_base_url, {sys}_api_client)
```

## 3. 完整接入：替换 6 大绑定点

### 3.1 配置层（`.env` → 新增 `.env.{SYS}`）

`SA_BASE_URL` / `SA_LOGIN_NAME` / `SA_PASSWORD` / `SA_ROLES_JSON` 全部替换为新系统同名配置。
**命名建议**：新系统专用前缀（如 `{SYS}_BASE_URL`），与 `SA_*` 并存，互不干扰。

### 3.2 登录/会话 adapter（`support/fixtures/{sys}.py`）

以 `smartadmin.py` 为骨架删改，只保留通用骨架（`CleanupRegistry` / `make_*_fixture_functions` / `pytest_collection_modifyitems` 结构），替换以下业务实现：

**① 登录 `{sys}_login`（三种形态模板）**

```python
# 形态A：匿名直连 —— 无需登录，登录函数直接 return
def {sys}_login(client, **kw):
    return

# 形态B：固定 token
token = os.getenv("{SYS}_TOKEN", "").strip()
client.token = token          # 后续请求自动带 Authorization: Bearer <token>

# 形态C：登录接口 + token（最常用）
resp = raw.post(f"{base}/login", json={"loginName": name, "password": pwd})
client.token = resp.json().get("data", {}).get("token")
# 若 token 走 Cookie：ApiClient 底层是 httpx.Client，天然维护 cookie jar，
# 登录请求后无需再注入，后续请求自动带会话 Cookie。
```

**② 会话过期自动重登**：沿用 `ApiClient.set_relogin_hook([未登录码], lambda: {sys}_login(client))`，把「SmartAdmin 探测出的未登录码」换成目标系统未登录响应特征。

**③ 角色池（可选）**：若新系统有 RBAC，把 `SA_ROLES_JSON` 换成 `{SYS}_ROLES_JSON`，其余复用 `load_*_roles` / `get_role_client` / `make_role_client_fixture` 骨架逻辑。

### 3.3 业务码探测（`smartadmin.py` 最大的坑）

原 `sa_probe_business_codes` **把探测逻辑写死到 SmartAdmin 业务接口**：

| SmartAdmin 探测项 | 写死的接口 | 换 {SYS} 的改法 |
|---|---|---|
| `dup_*`（重名失败码） | `POST /oa/enterprise/create` 连续建 2 次同名 | 找一个「创建时重名会失败」的实体接口 |
| `delete_not_exist` | `GET /oa/enterprise/delete/999999999` | 目标系统的「删除不存在 id」接口 |
| `forbidden`（越权码） | 低权限角色调 `POST /oa/enterprise/update` | 目标系统的「越权」成对接口 |
| `unauth`（未登录码） | 匿名 `GET /oa/enterprise/get/1` | 目标系统任意需鉴权的接口 |

**做法**：改成一个 `{sys}_probe_business_codes`，用目标系统的成对接口探测；没有对应场景就直接留 `None`（断言里不引用即可），不要硬造。

**2026-09-01 机制升级（务必对齐，否则反例退化成空壳）**：

1. **探测语义组 `_PROBE_GROUPS`**：一次探测成功后，用 `_fill_codes("组名", code)` 回填**整组同义键**——接口文档里的 key（如 `enterprise_name_duplicate`）与探测动作的键（`dup_enterprise`）同语义，一起回填，保证 `biz_fail("接口文档key")` 能命中。
2. **`{SYS}_CODES` 必须保持显式字面量**（`{"key": None, ...}`）：平台生成侧用 **AST** 解析它的键清单喂给 AI，写成推导式（`{k: None for ...}`）解析不到 → AI 的 `biz_fail` 无法对齐 → 反例全部退化。
3. **`param_error` 探测**：用"缺必填字段"的请求触发参数校验失败，回填 `param_error` 键（原 4 组不覆盖参数错误）。
4. **接口文档 key ↔ 探测键对齐**：接口文档 `business_codes` / `common_error_codes` 里的每个 key，要么在 `{SYS}_CODES` 直接存在，要么属于某个 `_PROBE_GROUPS` 语义组；对不上的 key 会打印 `[反例断言降级]` 警告（运行时可见），反例等于白测。
5. 完整参考：`support/fixtures/smartadmin.py` 的 `_PROBE_GROUPS` + `SA_CODES`（9 键） + `_fill_codes` 实现。

### 3.4 清理注册表适配

`CleanupRegistry` 通用，但 `register_delete` 注册的是 **SmartAdmin 式删除路径**（`GET /xxx/delete/{id}`，见 `smartadmin.py` 的 `flush()`）。
目标系统的删除形态若不同（如 `DELETE /xxx/{id}`、`POST /xxx/delete` + body），改 `flush()` 里的请求发送方式即可，注册表结构不用动。

> 纯 RESTful 系统用 `DELETE` 方法时，`ApiClient.request` 支持直接指定 method。

### 3.5 信封断言守卫（`support/api_case.py`）

守卫逻辑（`run_case` 内）：**payload 是 dict 且含 `ok` 键**才自动追加 `biz_ok`（`/ok eq true` 且 `/code eq 0`）。

| 新系统形态 | 改法 |
|---|---|
| A（含 `ok` 键） | 不用动 |
| B（`{code,msg,data}`） | 把 `Assertion.biz_ok()` / `biz_fail()` 改为断言 `/code eq 0` / `/code eq 目标码`（去掉 `/ok` 两条） |
| C（纯 HTTP） | 不改源码，用例统一 `biz_auto=False` + 显式状态码断言（见第 2.3 节示例） |
| D（混合） | 信封模块开 `biz_auto=True`，纯 HTTP 模块设 `False`，按模块约定 |

> 只要目标系统响应**不含 `ok` 键**，现有守卫就不污染断言——这就是"半通用"的边界。
> 成功码不是 0 的系统（如 `code=200` 才算成功），单独改 `biz_ok()` 里的 0 即可，全局生效。

### 3.6 token 注入方式（`support/clients/api_client.py`）

当前默认「登录后 `Authorization: Bearer <token>`」（见 `api_client.py` 登录态处理）。
- Cookie 会话型：天然支持（httpx cookie jar），无需改。
- 自定义 Header（如 `X-Auth-Token`）：在 `request()` 里读 `client.token` 时改注入位置，或给 `ApiClient` 加一个 `token_header` 属性。
- 建议：给 `ApiClient` 增加 `token_header: str = "Authorization"` + 前缀常量，避免到处散落 Bearer 假设。

### 3.7 根 `tests/conftest.py` 去掉硬引用

把 `from support.fixtures.smartadmin import SA_ROLE_CLIENTS` 改为**注册式**：

```python
# 旧：from support.fixtures.smartadmin import SA_ROLE_CLIENTS
# 新：会话池统一放一个注册表，各系统 adapter 往里面挂自己的 clients
def _active_api_clients(item):
    clients = []
    try:
        clients.append(item._request.getfixturevalue("api_client"))
    except BaseException:
        pass
    from support.fixtures.client_registry import ALL_CLIENTS  # 新注册表
    clients.extend(ALL_CLIENTS)
    return clients
```

各系统 adapter 登录成功后把自己 register 进去，SmartAdmin 与 `{SYS}` 可并存（日志打印都能看到）。

### 3.8 marker / 跳过逻辑

- 原 `smartadmin` marker + `SA_PASSWORD` 空即全量 SKIP → 换成 `{sys}` marker + `{SYS}_PASSWORD`（或 `{SYS}_TOKEN`）空即 SKIP，逻辑照搬 `smartadmin.py::pytest_collection_modifyitems`。
- `requires_role` marker 保留（算子级跳过），只换 `has_*_role` 内部读取的配置键。

### 3.9 契约生成对接（`tools/openapi_gen.py`）

把 OpenAPI 地址从 SmartAdmin 的 `…/v3/api-docs` 换成目标系统地址（或做成参数），生成 `tests/api/{sys}/test_*.py` 骨架，再按项目规范的「parametrize 展开 + 信封/状态码断言」补齐。

## 6. 从 SmartAdmin 踩坑经验里直接继承的注意事项

1. **密码加密协议**：目标系统若前端加密（SM4/AES/RSA），登录 adapter 必须对齐前端协议，明文直传会被判"密码错误"（SmartAdmin SM4 即此坑）。
2. **验证码**：测试环境若走 dev 明文 captcha，adapter 里自动解；否则留配置位或临时开关。
3. **账户锁定**：目标系统若有多设备/失败锁定，登录 adapter 要一次成功，连续失败会锁定账号（SmartAdmin 锁在 DB 表 `t_login_fail`，重启后端无效）。
4. **软删除**：SmartAdmin 删除是逻辑删除（`deleted_flag=1`）。换系统时确认删除语义，避免"删了还能查到"的断言假阳性（这是 SmartAdmin 已暴露的后端缺陷）。
5. **业务码别写死**：一律走「探测 → `{SYS}_CODES` → 断言引用」，不要在用例里硬编码业务码，换环境/版本才不用改。
